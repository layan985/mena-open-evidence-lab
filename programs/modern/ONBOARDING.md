# MODERN Contributor Onboarding

## First 48 hours
1. Read `GOVERNANCE.md`, `OPERATIONS.md`, `DATASET_STANDARD.md`, and `QA_CHECKLIST.md`.
2. Join one pod only at first.
3. Add or verify your contributor registry entry after your first accepted contribution.
4. Claim one scoped GitHub issue with a defined owner, reviewer, deadline, and deliverable.
5. Reproduce one small existing pipeline before starting new collection work.

## First contribution
A valid first contribution should be small enough to review in under 60 minutes. Examples:
- correct a source/provenance record
- add a validation test
- standardize one table
- document one identifier mapping
- improve one codebook section
- reproduce one released transformation

## Working rules
- Never edit raw source files manually.
- Never commit secrets or restricted data.
- Never claim affiliation, partnership, policy use, or release status without evidence.
- Ask about licensing before scraping or redistributing unclear sources.
- Use issues for decisions that affect released data.
- Prefer small reviewable PRs over giant unreviewable dumps.

## Credit
A person becomes a counted contributor only after a substantive contribution is merged or they are credited on a validated release with evidence.

## Leaving the network
Contributors can leave at any time. Their verified historical contributions remain credited. Unfinished work should be transferred or closed explicitly.
