# MODERN — First 30 Days

The first month exists to prove the operating system works with real people and real releases.

## Week 1 — recruit operators, not audience
- Open contributor applications.
- Recruit 3 interim Pod Leads for the highest-readiness areas: Labor Markets, Financial Markets, Narratives + Institutions.
- Recruit at least 2 external methodological reviewers.
- Create the first 6 scoped dataset issues.
- Run one public orientation / reproducibility session.

## Week 2 — ship the first small objects
- Select first contributors using `SELECTION_RUBRIC.md`.
- Onboard contributors using `ONBOARDING.md`.
- Put every person on one reviewable issue only.
- Release 1 small, excellent dataset or reconstruction with full QA and citation metadata.
- Ask one external researcher to independently reproduce it.

## Week 3 — prove external usefulness
- Release a second object from a different pod.
- Contact 10 researchers/policy analysts with a concrete dataset or method relevant to their work.
- Ask for one specific use case or defect report, not endorsement.
- Hold Workshop 01 with public materials and attendance evidence.

## Week 4 — audit the institution
- Publish the generated impact scoreboard.
- Publish one correction/failure log if any issue occurred.
- Review contributor throughput and reviewer bottlenecks.
- Close inactive work instead of inflating membership.
- Decide which pods have earned continuation based on shipped work.

## Day-30 proof target
Targets are not claims until evidenced.
- 5–8 counted contributors
- 3 universities represented
- 2 validated public releases
- 1 completed workshop
- 1 independent reproduction or external review
- 1 documented external use case or active institutional deliverable

If these are not achieved, reduce scope before increasing recruitment.
